# 개인정보 수동 삭제 운영 (자동 파기 없음)

개인정보처리방침과 같은 기준입니다. 자동 파기 기능은 없으므로 **운영자가 정해진 주기(권장: 매월 1회)와 이용자 삭제 요청 때** 아래 순서로 처리합니다.
모든 삭제는 **먼저 SELECT로 대상을 확인 → DB 백업 확인 → 트랜잭션 안에서 실행 → 건수 확인 후 COMMIT** 순서로 합니다. (운영 DB 접속 방법은 `출시-점검표.md` 참고. 아래 SQL은 예시이며 이 문서 작성 중에는 실행하지 않았습니다.)

## 1. 보관 기준 표

| 구분 | 대상(테이블·컬럼) | 보관 기간 | 근거 | 기간이 지나면 |
|---|---|---|---|---|
| 결과지·사주 원문 (성공운명서) | `orders.input`(아이 성별·생년월일·시간·이름), `analysis_jobs.events` / `result_text` | 결제 후 **1년** | 개인정보처리방침 제3조 | 삭제(익명화) |
| 결제 거래 기록 (**법정 보관**) | `orders`의 `id`, `amount`, `paid_amount`, `paid_at`, `imp_uid`, `email`, `refund_*` | **5년** | 전자상거래법(거래 기록) | 5년 지난 뒤 삭제 |
| 무료 체험 주문 (결제 없음, `is_comp = true`) | `orders` 행 전체, `analysis_jobs` | 1년 | 결제가 아니므로 거래 기록 의무 없음 | 주문 행 통째로 삭제 |
| 체험 코드 | `trial_codes`(`code_hash`, `email_hash` 해시만) | 사용·만료 후 1년 | 중복 사용 방지 | 삭제 |
| 후기 | `reviews`(닉네임·별점·내용) | 이용자가 삭제를 요청할 때까지 | 방침 제3조 | 요청 시 즉시 삭제 |
| 재열람 인증번호·열람 토큰 | `result_otps`, `result_sessions` | 자동 삭제됨(만료 1일 뒤/만료 즉시) | 서버 정리 작업 | 별도 처리 없음 |
| 이메일 발송 기록 | `email_sends`(수신자 해시) | 자동 삭제됨(7일) | 서버 정리 작업 | 별도 처리 없음 |
| 다른 상품(사주·궁합·심화·길일·100년)의 결과 | `results`(이메일·결과·이름), `orders` | 이용자 삭제 요청 시 | 방침 제3조 | 요청 시 삭제. 결제 건의 거래 기록은 5년 보관 |

**법정 보관 대상 구분 핵심**: 유료 주문의 `orders` 행(금액·결제일·주문번호·결제번호·이메일·환불 기록)은 5년 보관이므로 **행을 지우지 않고**, 1년이 지나면 사주 원문(`input`)과 결과지(`analysis_jobs`)만 지웁니다.

## 2. 월 1회 정기 삭제 (1년 경과분)

```sql
BEGIN;
-- (1) 대상 확인
SELECT id, is_comp, paid_at FROM orders
 WHERE product = 'success_child' AND paid_at < NOW() - INTERVAL '1 year';

-- (2) 유료 주문: 거래 기록은 남기고 사주 원문·결과지만 삭제
UPDATE orders SET input = '{"purged": true}'::jsonb
 WHERE product = 'success_child' AND is_comp = false AND paid_at < NOW() - INTERVAL '1 year';
DELETE FROM analysis_jobs WHERE order_id IN
 (SELECT id FROM orders WHERE product = 'success_child' AND paid_at < NOW() - INTERVAL '1 year');

-- (3) 무료 체험 주문: 행 통째로 삭제(analysis_jobs 는 자동 연쇄 삭제). 연결된 후기도 함께 삭제
DELETE FROM reviews WHERE order_id IN
 (SELECT id FROM orders WHERE product = 'success_child' AND is_comp = true AND paid_at < NOW() - INTERVAL '1 year');
DELETE FROM orders WHERE product = 'success_child' AND is_comp = true AND paid_at < NOW() - INTERVAL '1 year';

-- (4) 사용·만료된 체험 코드 정리
DELETE FROM trial_codes WHERE COALESCE(used_at, expires_at) < NOW() - INTERVAL '1 year';

-- 건수 확인 후 문제가 없으면 COMMIT, 이상하면 ROLLBACK
COMMIT;
```
> 유료 후기(`usage_kind = 'paid'`)는 주문과 별개로 이용자가 삭제를 요청할 때만 지웁니다.
> 재열람 목록은 `paid_at` 기준이 아니라 `input` 이 비워진 주문이면 결과지가 없어 "만들고 있습니다"로 보일 수 있으니, 삭제 전에 해당 이용자에게 영향이 없는지(1년이 지난 건인지) 꼭 확인합니다.

## 3. 5년 경과 거래 기록 삭제 (연 1회)
```sql
BEGIN;
SELECT id, paid_at FROM orders WHERE paid_at < NOW() - INTERVAL '5 years';
DELETE FROM reviews WHERE order_id IN (SELECT id FROM orders WHERE paid_at < NOW() - INTERVAL '5 years');
DELETE FROM orders WHERE paid_at < NOW() - INTERVAL '5 years';
COMMIT;
```

## 4. 이용자 삭제 요청 처리 (요청 접수 후 지체 없이)
1. 요청자가 **구매 때 입력한 이메일의 소유자인지** 확인합니다(해당 이메일로 답장·확인). 아이 정보 요청은 보호자(법정대리인)만 가능합니다.
2. 대상 주문 확인: `SELECT id, product, is_comp, paid_at FROM orders WHERE lower(email) = lower('<이메일>');`
3. 백업 확인 후, 트랜잭션에서 처리:
```sql
BEGIN;
-- 결과지·사주 원문 삭제(유료는 거래 기록 행 유지, 체험은 행 삭제)
DELETE FROM analysis_jobs WHERE order_id IN (SELECT id FROM orders WHERE lower(email) = lower('<이메일>'));
UPDATE orders SET input = '{"purged": true}'::jsonb WHERE lower(email) = lower('<이메일>') AND is_comp = false;
DELETE FROM reviews WHERE order_id IN (SELECT id FROM orders WHERE lower(email) = lower('<이메일>') AND is_comp = true);
DELETE FROM orders WHERE lower(email) = lower('<이메일>') AND is_comp = true;
-- 후기 삭제 요청이 있으면 유료 후기도 삭제
DELETE FROM reviews WHERE order_id IN (SELECT id FROM orders WHERE lower(email) = lower('<이메일>'));
-- 다른 상품 결과(있다면)
DELETE FROM results WHERE lower(email) = lower('<이메일>');
DELETE FROM result_otps WHERE email = lower('<이메일>');
DELETE FROM result_sessions WHERE email = lower('<이메일>');
COMMIT;
```
4. 결제 거래 기록(금액·결제일·주문번호·이메일)은 전자상거래법상 5년 보관 대상이라 지우지 않는다고 요청자에게 안내합니다.
5. 처리 일시·요청자(이메일 해시 말고 식별 가능한 메모는 개인정보이므로 최소한)·처리 내용을 운영 일지에 남깁니다.
